# 1. Бизнес-контекст, драйверы и цели

* Проблема: Рост числа конкурентов перешедших в онлайн продажу.
* Причина: Глобальное падение продаж на 15% ввиду пандемии.
* Цель: Реализовать цифровые каналы продажи алмазов.
* Результат:
    1. Достаточность технологической базы для проведение цифрового аукциона через 2 месяца
    2. 100% автоматизированный процесс проведения онлайн-аукциона.
    3. Снижены риски зависимости от внешних сервисов, сотрудников, неэффективного использования ресурсов до минимума.

# 3. Ключевые требования и ограничения
## 3.1 Бизнес-требования
 * BR-01. Целевое решение должно полностью автоматизировать и отладить процесс подготовки и проведения онлайн-аукциона
 * BR-02. Целевое решение должно снизить риски зависимости от внешних сервисов, конкретных сотрудников, неэффективного использования ресурсов.
 * BR-03. Необходимо реализовать MVP процесс без доработки систем для проведения аукциона через два месяца.
 * BR-04. Оцифровка алмазов должна быть реализована на стороне подрядчика или облачных сервисов.

## 3.2 Нефункциональные требования
## BR-01 NFR:
* NFR-01. Длительность актуализации данных по алмазам не более 1 часа
* NFR-02. Актуализация статуса торгов не дольше 1 минуты
## BR-02 NFR:
* NFR-03. SLA доступности онлайн витрины алмазов не менее 99,95% - доступность клиентского интерфейса для просмотра информации про алмазы и статуса торгов
* NFR-04. RPO локальной витрины алмазов не свыше 2 часов 
* NFR-05. RPO статуса по торгам и сделок стремится не свыше 1 минуты
* NFR-06. RTO витрины алмазов и статуса по торгам не свыше 15 минут
## BR-03 NFR:
* NFR-07. MVP решение должно позволять ручное внесение и корректировку данных уполномоченных сотрудников через UI

# 4. Архитектурные принципы
**Least Privilleges**. Принцип наименьших полномочий - каждому сотруднику предоставляется доступ к определенному внутреннему сервису через Role-Based structure. Роль определяется на основе функции сотрудника. Принцип позволяет снизить риски связанные с нарушением работы сервисом ввиду необосновано широких полномочий сотрудников.

**API First**. Интерфейсы взаимодействия компонентовв проектируются и согласуются до реализации самих компонентов. API рассматривается как самостоятельный контракт и продукт. Принцип позволяет снизить издержки на доработку существующих интеграций при появлении нового комопнента в цепочке.

## 5. Область охвата
**Breadth**. Областью рассмотрения предприятия является:
* Проведение внутреннего аукциона;
* Отцифровка алмазов;
* Логистику алмазов.

**Depth**. Описываем концептуальную и логические архитектуры.

**Domains**. Рассматриваем следующие домены архитектуры:
* Архитектуру данных;
* Архитектуру приложений.

**Time period**. Рассматриваем архиткуру в двух временных промежутках:
* Через два месяца - MVP архитектура для проведения аукциона;
* Через год - целевая архитектура.

# 6. Общее представление архитектуры.
## 6.1 AS IS
Текущая архитектура предусматривает:
* предаврительное получение сведений об ассортименте (консультации, реклама, газеты, брошюры и т.д);
* непосредственное участие клиента в аукционе;
* возложение на самого клиента процесс по приходу на место проведения аукциона;
* физическое приобритение выигранного лота;
* возложение на самого клиента процесс по возвращению обратно.

![AS-IS диаграмма](<DIamonSolution-High AS IS.drawio.svg>)

## 6.2 MVP
Промежуточная или минимально достаточная архитектура, для проведения аукциона онлайн, предусматривает:
* ручную регистрацию заявки на онлайн аукцион;
* ручное обновление статуса акциона на облачном сервисе;
* ручное формирование списка онлайн-победителей с указанием выигранных лотов;
* использование облачных сервисов по проведение оплат, с ручным формированием заказа;
* ручную организацию доставки лотов победителям через альтеранитвые логистические решения.

Схема представляет альтернативный flow с участим клиента в онлайн аукционе, не заменяя собой оффлайн аукцион.

![MVP диаграмма](<DIamonSolution-High MVP.drawio.svg>)

## 6.3 TO BE
Целевая архитектура предусматривает:
* интеграции с контрагентами по отцифровки алмазов;
* публикацию отцифрованных алмазов на онлайн витрину;
* предоставление клиенту онлайн инструменту по выбору желаемого лота;
* онлайн участие клиента в торгах;
* проведение клинетом онлайн оплаты через онлайн кассу;
* передача выигранного и оплаченного лота в службу доставки организации;
* автоматизированый учёт онлайн торгов;
* автоматизированное выставление счёта и онлайн оплату;
* получение клиентом лота через доставку.

В целевой схеме устраняется ручной фактор проведения операций из MVP схемы, взамен автоматизации межсистемной интеграции для уже существующих систем.
